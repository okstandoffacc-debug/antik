# Старинная Коллекция — подключение регистрации и админ-панели

Сайт по-прежнему статический и может размещаться на GitHub Pages. Supabase используется для регистрации/входа и общей базы товаров.

## Что добавлено
- Регистрация покупателей и вход по email/паролю.
- Все новые аккаунты получают роль `user` автоматически.
- Страница `admin.html` для добавления, редактирования и удаления товаров.
- Доступ к управлению товарами ограничен на стороне базы данных (RLS), а не только скрытием кнопки.
- Кнопка импорта исходного `catalog.js` в новую базу, чтобы перенести существующие товары.
- Если Supabase ещё не настроен, сайт продолжает показывать исходный локальный каталог.

## Настройка (один раз)

1. Создайте проект на [Supabase](https://supabase.com/).
2. В Supabase откройте **SQL Editor → New query**, вставьте содержимое `supabase-schema.sql` и нажмите Run.
3. Откройте `js/config.js`. В `window.SUPABASE_CONFIG` замените:
   - `url` на Project URL из **Project Settings → API**;
   - `anonKey` на публичный `anon` key (или publishable key) из того же раздела.

   **Никогда не помещайте `service_role` / secret key в файлы сайта.** Публичный ключ безопасен для клиентского использования только вместе с настроенными RLS-политиками.
4. Опубликуйте обновлённые файлы на GitHub Pages.
5. Откройте опубликованный сайт и зарегистрируйте аккаунт отца на его email. Если включено подтверждение почты, сначала подтвердите email.
6. Вернитесь в Supabase → SQL Editor и выполните, подставив реальный email отца:

   ```sql
   update public.profiles
   set role = 'admin'
   where email = 'father@example.com';
   ```

   Сделайте это только для email отца. Не добавляйте регистрацию на сайте с выбором роли администратора.
7. Войдите на сайте под аккаунтом отца, затем откройте `admin.html` (ссылка «Админ-панель» появится после входа, когда роль будет назначена).
8. Нажмите **«Импортировать исходный каталог»**. Это переносит товары из текущего `js/catalog.js` в общую базу. После успешного импорта каталог сайта будет загружаться из Supabase.

## Важные замечания
- Обычные пользователи могут зарегистрироваться и просматривать каталог, но не могут менять товары: это запрещают политики RLS в Supabase.
- Не удаляйте и не изменяйте роль `admin` у аккаунта отца.
- Если `products` в базе пустая, сайт использует исходный каталог как запасной вариант. После импорта все изменения админ-панели сохраняются в Supabase и видны посетителям.
- Корзина, избранное, история и часть личного кабинета в исходном проекте всё ещё хранятся локально в браузере. Они не синхронизируются между устройствами и не являются полноценной серверной системой заказов.
- Для регистрации нужен интернет и корректно настроенный проект Supabase.
